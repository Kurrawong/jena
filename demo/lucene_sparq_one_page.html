IRIs abbreviated below for readability (urn:title, urn:year, urn:sourceGraph)
# Typical combined shape - hits + per-field match UNION facets SELECT * WHERE { { ( ?hit ?entity ?score ?totalHits ) luc:query ( ★"primary" '["urn:title", "urn:description"]' ★"machine learning" ★"" '{"field":"urn:year","order":"desc"}' 20 0 ) . ( ?hit ?field ?value ?snippet ) luc:match ( ) . } UNION { ( ?field ?value ?value_low ?value_high ?count ) luc:facet ( ★"primary" "default" ★"machine learning" '["urn:category", {"field":"urn:year", "ranges":[null, 2020, 2022, 2024, null]}]' ★"" 10 2 ) . } }
★Shared Search Inputs These marked inputs normally stay aligned across luc:query and luc:facet so the facet buckets describe the same search as the hit query. Graph scoping is a normal CQL filter on a reserved synthetic field such as urn:sourceGraph.
?hitblank-node join key for luc:match (required)
?entitymatched entity IRI
?scoreLucene relevance score (xsd:float)
?totalHitsfull match count across the result set, independent of limit / offset - only computed when projected
?hitsame blank-node as luc:query - this is the join
?fieldfield IRI that matched
?valuestored value - KEYWORD→IRI, TEXT→string, numeric→typed literal
?snippetreserved slot for future highlight output; may be unbound for now
?fieldfacet field IRI
?valueflat or hierarchical value - unbound on range-bucket rows
?value_lowrange lower bound - inclusive; unbound on flat rows
?value_highrange upper bound - exclusive; unbound on flat rows
?countdocument count (xsd:long)
luc:queryruns the Lucene search and binds hit-level metadata for matching documents
indexSelectorrequired first arg - configured text:indexId or index IRI
fieldSpec"default" or a JSON array of field IRIs to scope the search
queryStringLucene classic parser text
cqlFilterCQL2-JSON object, or "" when intentionally absent
sortSpecJSON sort object or array using field IRIs, or ""
limitinteger literal cap; lexical forms like "10" are accepted; negative = unlimited
offsetnumber of leading hits to skip; 0 = first page; must be non-negative
luc:matchthe only per-hit match-detail API; object is always ()
luc:facetruns the same search shape but returns aggregated facet buckets instead of individual hits
indexSelectorsame selector model as luc:query
fieldSpecsearch scope for the facet search; may differ from the hit query
queryStringsame query text; use "*" to facet across every indexed document
facetFieldsfield IRIs and/or range objects; null inside ranges means an open end
cqlFiltersame empty-string sentinel as luc:query; graph scoping belongs here via urn:sourceGraph
maxValuesper-field cap on returned values; 0 = all
minCountdrop long-tail values below this count
positional arg filter / sort arg numeric arg subject / bindings
Fixed arity: luc:query takes 7 object args and luc:facet takes 7.  ·  Empty slots: use "" for absent cqlFilter / sortSpec.  ·  Graph filtering: target model is a normal filter on urn:sourceGraph, not a dedicated result slot.  ·  Shared execution: matching selector + query + filter state across the PFs reuses one Lucene search.
